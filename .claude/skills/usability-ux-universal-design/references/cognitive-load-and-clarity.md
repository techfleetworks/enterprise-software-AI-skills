# Reducing Cognitive Load & Making It Obvious

The scarcest resource in any interface is the user's attention and working memory. Every
decision, every thing to remember, every ambiguous element spends it. Usable design spends
as little as possible, so the interface is understood at a glance.

## Recognition over recall

Human working memory holds only a few items at once. Don't make users remember — show them:

- Present choices (menus, pickers, suggestions) instead of requiring recalled commands,
  codes, or exact syntax.
- Keep already-entered data visible; carry context forward between steps rather than making
  users re-remember it.
- Surface recent/likely items and sensible defaults so the common path is a recognition,
  not a memory test.

## Clear affordances and signifiers

- **Things that do something must look like they do it.** Buttons look pressable; links look
  linky; inputs look editable. Don't disguise controls as decoration or vice versa.
- **One obvious primary action per screen.** Make the main action visually dominant; make
  secondary actions quieter; don't present five equally-weighted buttons.
- **Signal state**: disabled, selected, loading, expanded — show it, don't leave users
  guessing whether something is interactive or already done.

## Visual hierarchy, grouping, and space

- Use size, weight, color, and position to show what matters most — the eye should land on
  the important thing first.
- **Group related things** (proximity, borders, sections) so structure is obvious; separate
  unrelated things. Related controls near what they affect.
- **Whitespace is not wasted space** — it reduces clutter, separates groups, and makes dense
  UIs readable. Crowded interfaces raise cognitive load.

## Progressive disclosure

Show what's needed for the current task; reveal complexity on demand. Defaults and the
common case up front; advanced options behind "More," an accordion, or a later step. This
keeps novices from drowning while still serving experts — and shortens the perceived
length of forms and flows.

## Consistency and convention

- **Internal consistency**: the same element/word/action behaves identically across the
  product. Inconsistency forces users to re-learn and re-check.
- **External consistency**: follow established platform and web conventions (nav placement,
  icons, gestures, primary-button side). Novelty here is a cost, not a feature — reserve
  creativity for where it adds real value, not for relearning basics.

## Reduce effort in inputs

- **Smart defaults** for the most likely choice, so many users can just proceed.
- **Forgiving inputs**: accept phone numbers/dates in multiple formats and normalize them;
  trim whitespace; don't reject a card number because of spaces.
- **Autofill, pickers, and inline suggestions** instead of demanding precise manual entry.
- **Minimize required fields and steps** — every one is friction and a chance to drop off.

## Guide attention and set expectations

- **Feedback for every action** (see visibility of system status) so users know it worked.
- **Set expectations** before long or consequential actions ("This may take a minute," "This
  can't be undone").
- **Don't overload with simultaneous demands** — one clear focus per screen beats a wall of
  competing options. When everything is emphasized, nothing is.
